# 多工作区 + 多 agent 转发

## Context

当前服务是「多对一」：所有用户固定路由到 `multica.workspace_id` + `multica.agent_id` 配置的单一 agent。需要升级为「多对多」：**会话内先选工作区、再选该工作区下的 agent**，不同会话可路由到不同目标。

探索结论（切口很干净）：
- 路由决策只集中在 `conversation.py` 两处：`converse()` 里 `self.settings.agent_id`（137 行 upsert、154 行 `create_issue(assignee_id=...)`）
- `sessions` 表已有 `agent_id` 列但只写不读；需新增 `workspace_id` 列（含旧库迁移）
- 钉钉/REST 都汇聚到 `converse()`，天然是加参数的缝隙
- agent 绑定在 issue 上：**切换目标 = 清除 issue 绑定，下一条消息新开会话**（技术必然）
- `MulticaClient` 的 `--workspace-id` 是构造时固化的全局 flag，需改为支持按调用覆盖；`list_workspaces()` 需新增（CLI 已支持 `multica workspace list`）

## 配置模型（别名 + UUID 都支持）

```yaml
multica:
  workspace_id: <默认 ws UUID>     # 兼容现状：默认目标
  agent_id: <默认 agent UUID>
  workspaces: {main: ws-uuid, docs: ws-uuid2}   # 可选别名
  agents: {coder: agent-uuid, writer: agent-uuid} # 可选别名（别名只是 ID 快捷方式，不绑定所属 ws）
```

- 环境变量：`MDS_MULTICA_WORKSPACES` / `MDS_MULTICA_AGENTS`（JSON 对象字符串）；空值自动跳过
- 同一 server_url/profile 下的多工作区（跨服务器认证不在本次范围）

## 改动清单

**1. `app/settings.py`** — `MulticaSettings` 加 `workspaces/agents: Dict[str,str]`；env 覆盖表加两个 JSON 解析项；加 `resolve_workspace(s)` / `resolve_agent(s)` 辅助方法：别名→UUID，本身是 UUID/未知串则原样返回，供 bot 与 api 共用。

**2. `app/store.py`** — sessions 表加 `workspace_id TEXT` 列；`SessionStore.__init__` 里用 `PRAGMA table_info` 检测旧库并 `ALTER TABLE ADD COLUMN`（无破坏迁移）；`upsert_session` INSERT 带上 workspace（ON CONFLICT 不更新，保持现状语义）；新增 `set_session_target(key, workspace_id, agent_id)`：更新目标列并清空 `issue_id/issue_key`（下一条消息新建 issue）。

**3. `app/multica_client.py`** — `_run()` 加 `workspace_id: Optional[str]` 覆盖参数（None 用 self 默认）；`create_issue/list_agents/add_comment/list_runs/run_messages/list_comments/get_issue/delete_issue` 透传；新增 `list_workspaces()`。

**4. `app/conversation.py`** — `converse()` 加可选 `workspace_id/agent_id` 参数；生效优先级：**本次参数 > 会话已存 > settings 默认**；新建 issue 用生效的 ws+agent 并 upsert 存档；已绑定 issue 的评论/轮询操作用会话存的 workspace；`meta` 事件带上 workspace/agent；issue 标题从硬编码 `"DingTalk 会话"` 改为按 channel，并追加 agent 别名便于在 multica 界面区分。顺手补 `typing.List` import（探索发现靠 `__future__` annotations 掩盖的缺失）。

**5. `app/dingtalk_bot.py`** — 命令链（`_handle` 内，`/issue` 之后）新增：
- `/ws` — 当前工作区 + 可选工作区列表（别名优先展示，无别名配置时 live 调 `list_workspaces()` 显示名称+UUID）
- `/ws <别名|UUID>` — 切工作区（同时清 agent 绑定 + 重置会话）
- `/agent` — 当前 agent + 当前工作区下 agent 列表（live 调 `list_agents(ws)`，过滤 archived）
- `/agent <别名|UUID>` — 当前工作区内切 agent
- 切换前用 `list_agents` 校验目标存在（防手滑），CLI 不可用时提示稍后再试、不切换；`/help` 文案同步更新

**6. `app/api.py`** — `ChatRequest` 加可选 `workspace_id/agent_id`（接受别名或 UUID，经 settings 解析后传入 converse）；新增 `GET /api/workspaces`；`GET /api/agents` 加 `?workspace_id=` 查询参数；`/api/info` 显示默认目标 + 别名表。

**7. 周边同步** — `config/config.example.yaml`、`.env.example`、`docker-compose.yml`（environment 加两个 JSON 变量透传）、`docker-compose.named-volumes.yml` 不变、README（架构图多对多、配置表、命令表、REST 参数、迁移说明）。
