# 多机器人接入（互相隔离）

## Context

当前服务只连一个钉钉机器人（一套 client_id/secret、一套白名单、一个默认路由目标）。需要支持**同时接入多个钉钉机器人**（多个开放平台应用），且互相不影响：各自的白名单、各自的默认工作区/agent、各自的会话/队列、各自的重连——一个机器人挂了不影响其他。

探索结论（可行性已验证）：
- dingtalk-stream SDK **支持同进程多客户端**：`DingTalkStreamClient` 全部状态为实例属性，无模块级单例；`async start()` 每实例独立 websocket + keepalive。注意事项：handler 必须每客户端新建（现有 `_BotHandler(self)` 已满足）；SDK 内部少量同步 requests 调用会短暂阻塞 loop（现状即如此，量级可接受）
- 仓库耦合点：`main.py:108-126`（create_app 单 bot）、`main.py:26-52`（lifespan 单 task）、`dingtalk_bot.py:206`（会话键 `dingtalk:{uid}` 无 bot 维度，多 bot 下同一 staffId 会撞会话）、`api.py` /health、/api/info 单状态
- 多 manager 共享同一 `SessionStore` 安全（前提：一个 session_key 只归一个 manager，由键分区保证）

## 配置模型（向后兼容）

```yaml
dingtalk:            # 现有配置 = 默认机器人，老部署零改动
  client_id/secret/白名单/card_title...

dingtalk_bots:       # 新增：额外机器人（config.yaml 配置，不走环境变量）
  ops:                       # slug：小写字母/数字/-，用于会话键与日志
    client_id: xxx
    client_secret: xxx
    card_title: 运维机器人
    allowed_staff_ids: [...] # 各自独立，不继承默认机器人（白名单绝不隐式继承）
    multica:                 # 可选：本机器人独立默认路由，缺省回落全局 multica.*
      workspace_id: ws-a
      agent_id: ag-x
      agents: {coder: ag-x}
```

## 改动清单

**1. `app/settings.py`**
- `Settings` 加 `dingtalk_bots: Dict[str, dict]`；`load()` 里 `dingtalk_bots=raw.get("dingtalk_bots", {})` 直传
- 新增 `iter_bots(settings) -> List[Tuple[slug, DingTalkSettings, MulticaSettings]]`：
  - 默认 bot：`("default", settings.dingtalk, settings.multica)`，键格式不变（老会话不丢）
  - 额外 bot：`DingTalkSettings(**cfg)`（`enabled=True` 强制）；multica 用 `dataclasses.replace(settings.multica, **cfg.get("multica", {}))` 只覆盖显式给出的键
  - 校验：slug 正则 `^[a-z0-9-]{1,32}$`、缺 client_id/secret 跳过并 warning、与已有 bot 的 client_id 重复 warning

**2. `app/dingtalk_bot.py`**
- `DingTalkBot.__init__` 加 `slug: str = "default"`
- `_handle` 会话键：default 保持 `dingtalk:{uid}`；额外 bot 用 `dingtalk:{slug}:{uid}`（`conversation.set_target` 的 `partition(":")` 解析 channel 不受影响）
- 其余（白名单、命令、卡片）已全部经 `self.bot.settings` / `self.bot.manager` 取值，天然按 bot 隔离，无需改

**3. `app/main.py`**
- `create_app`：store 与 MulticaClient 仍全局各一份；建一个**共享** `asyncio.Semaphore(max_concurrent_rounds)`（全局并发预算不随 bot 数翻倍）；对每个 bot spec 建 `ConversationManager(client, store, ms, shared_sem)` + `DingTalkBot(dt_settings, manager, slug)`；`app.state.dingtalk_bots: Dict[slug, bot]`，`app.state.dingtalk_bot`/`app.state.manager` 保留指向 default bot（REST 侧兼容）
- `lifespan`：每个 bot 独立 `create_task(_run_dingtalk(bot))`（重连退避已按 task 隔离）；per-bot 启动告警（缺凭证跳过 / 白名单为空）；关机 cancel 全部 + 逐个 `aclose()`

**4. `app/conversation.py`**
- `__init__` 加可选 `shared_sem: Optional[asyncio.Semaphore]`（None 则自建，默认行为不变）；`_active_rounds` 仍按 manager 计数（展示用）

**5. `app/api.py`**
- `/health`：保持现有 `dingtalk.{enabled,connected}`（指向 default bot，兼容监控），新增 `bots: {slug: {"connected": bool}}`
- `/api/info`：新增 `bots: {slug: {whitelist_size, workspace_id, agent_id}}`

**6. 周边**：`config/config.example.yaml` 加 `dingtalk_bots` 注释示例；README 增加「多机器人」小节（配置示例、会话/白名单/路由隔离说明、`max_concurrent_rounds` 为全局预算、SDK 注意事项）。

## 验证

1. 扩充 `/tmp/mds_multiagent_test.py`：双 bot 配置 → 双 manager 共享 store；同一 uid 在两个 bot 是独立会话、独立默认目标；slug 清洗与缺凭证跳过；`iter_bots` 组装正确；/health 返回 `bots` 映射；REST 路径不回归
2. `docker compose up -d --build` 后 `/health` 观察 `bots` 各自 `connected`
3. 用户侧实测：配置第二个钉钉应用，两个机器人各自对话互不影响；一个停用后另一个照常
